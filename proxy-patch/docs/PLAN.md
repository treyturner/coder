# Coder CLI proxy patch implementation plan

Recommendation as of October 17, 2026: prepare a narrowly patched CLI based on **Coder v2.37.4, commit `1d246291a8a6ae1948b8c825ee252f6a46bfd561`**, matching the stable server version the user now reports running. Retain its exact Tailscale fork pin. The WebSocket proxy omission remains present in v2.37.4 and v2.38.0. Public candidate patches exist, but neither is a verified released solution. Implement only after this research phase is approved.

The eventual deliverables should be versioned CLI Docker images mirrored to `ghcr.io` and `forgejo.treyturner.info`, accompanied by the patch source and build records. Keep this client artifact separate from a server deployment. No implementation, test execution, build, installation, publication, live SSH, server setting change, or credential creation was performed for this plan. Public repositories were cloned into subdirectories; the workspace root was not initialized as a Git repository.

The reported successful API access, workspace readiness, DERP HTTP 403, failed fallback, and separate WebSocket HTTP 101 are historical v2.36.7 deployment observations supplied with the task. The current CLI base therefore selects **x/net v0.58.0 and WebSocket v1.8.14**. Their `httpproxy.FromEnvironment` implementations use uppercase-first selection in v0.57.0 and lowercase-first in v0.58.0/v0.59.0 when both nonempty variants conflict. Preserve the current base's behavior for unambiguous settings; do not normalize production variables or claim identical selection across revisions. The reviewed implementation conservatively rejects any different nonempty upper/lowercase pair for HTTP_PROXY, HTTPS_PROXY or NO_PROXY before CLI API client initialization and every Tailscale proxy selection. With Go 1.26.5, the API's standard-library selector uses a separately vendored uppercase-first implementation. It can disagree with the current v2.37.4 base's external x/net selector when uppercase and lowercase settings conflict. Make API-versus-DERP selection an explicit release gate under the locked toolchain and reject ambiguous case variants at runtime before networking. Never print the values to diagnose the conflict. [Go vendored selection][govendor].

Comparing the two Coder release commits leaves the proposed patch scope unchanged. The SSH command, session provider, tailnet setup, build script and Docker recipes are unchanged; transport setup is semantically unchanged. ### Which proposed changes are necessary

`tshttpproxy.ProxyFromEnvironment` is the routing correction needed in the WebSocket transport. It preserves the pinned selector's uppercase/lowercase HTTP_PROXY, HTTPS_PROXY and NO_PROXY behavior, including cached environment configuration and platform proxy fallback. Do not add new ALL_PROXY semantics. On ordinary Linux, an environment NO_PROXY match yields direct operation; Windows/Synology system fallback needs separate platform qualification. [Cache][selector], [selector and platform fallback][selectimpl], [Linux fallback][linuxproxy].

For an HTTPS relay through an `http://` proxy, Go's transport already implements CONNECT and Basic proxy URL userinfo authentication. No new manual CONNECT implementation is needed. `GetProxyConnectHeader` calling `tshttpproxy.GetAuthHeader` adds parity for OS supplied authentication and the existing Tailscale auth hook; it does not fix routing by itself. Use a **silent local callback**, returning only `Proxy-Authorization` when nonempty, and a sanitized error on failure. Never install the logging convenience helper. Plain HTTP relay forward-proxy requests do not call this CONNECT callback; Basic URL auth is automatic, while any broader auth requirement is outside the initial Linux HTTPS-relay scope. [Auth implementation and unsafe helper][auth], [Go CONNECT and Basic auth][gotransport].

Distinguish `HTTPS_PROXY=http://...` from `HTTPS_PROXY=https://...`. The latter also requires TLS **to the proxy**. Go reuses `Transport.TLSClientConfig` for both TLS layers and preserves a nonempty ServerName. Here that configuration identifies the relay and can contain relay client certificates or verification callbacks. The one-line fix alone therefore cannot safely claim support for TLS proxies. Preserve the relay config and use a separate, verified outer proxy TLS config as described below. [Relay config][relaytls], [Go TLS configuration][gotls], [outer and inner TLS][gotransport].

The existing relay config uses `tlsdial.Config`, which implements certificate verification in a callback, including existing trust-root behavior. Its internal `InsecureSkipVerify` bit is not evidence that verification is disabled. Preserve those callbacks, roots, server identity, client certificates and HTTP/1.1 settings. Do not add a verification bypass. [Verifier][tlsverify].

## Credentials and policy

API/coordination session authentication, reverse-proxy access headers and egress proxy authentication serve different peers. Preserve the existing session provider for API and coordination requests. The CLI supplies DERP with its HeaderTransport headers, not an automatically copied Coder session token; DERP also performs its own node-key protocol authentication. Do not add the API token to every DERP host or to CONNECT. Send proxy authorization only to the selected proxy, outside the inner relay TLS tunnel. [Header propagation][sdkopts], [session provider][session].

Keep the DERP transport local. Reusing the whole API HTTPClient/HeaderTransport to obtain its proxy behavior could attach API credentials to alternate DERP hosts. Preserve `c.headers()` and its existing static/dynamic precedence instead.

Protected network-secret injection remains in the configured proxy/service mechanism. A placeholder need not be the real credential. Use existing protected bindings normally without reading secret stores, creating tokens, substituting extracted credentials, changing destinations or enabling direct egress. Build contexts, image layers, source manifests and CI artifacts must contain no runtime credentials, cookies, client private keys or environment dumps. Use runtime protected mounts/bindings for existing CA/auth configuration; preserve TLS verification and the inherited production proxy environment.

Never use shell tracing, verbose HTTP dumps, packet captures, TLS key logs or raw response bodies in live validation. Tests use only generated local keys/certificates and synthetic secret markers, assert marker absence in stdout/stderr/logs/errors/artifact metadata, and print only failure labels. The unsafe Tailscale logging helper must be absent. These controls also apply to failure paths and independent review.
